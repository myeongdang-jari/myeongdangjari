## 2. 지금 돈이 안 되는 이유 — 전환 병목 3가지

돈이 안 되는 원인은 트래픽이 아니라 **무료로 본 사람이 결제까지 가는 길에 구멍이 있다**는 쪽이다. 아래 3개가 이번 주 안건이다.

### 병목 A. 서버 PDF 생성·동 호수 매칭 안정성
**현상**
- 자동 생성이 멈춘 채 사람이 손으로 풀어 줘야 하는 건이 반복 발생했다(최근 며칠 사이 여러 건 누적). 멈춘 이유는 대개 리포트 안의 표·수치 검사(예: 반경 상권 표기 빈칸)에서 걸린 것이다.
- 신청한 동과 다른 동으로 발행되는 매칭 오류가 실제 고객에게 나갔다(102동 신청 → 103동 발행). 고객이 "구조가 다른데 결과에 상관 있나요"라고 물어온 사례가 있다.
- 발송 지연 문의("메일이 안 와서요")가 발생했고, 원인은 같은 실패 누적이었다.

**왜 매출에 걸리나**
결제는 이미 됐는데 상품이 안 오는 상태다. 이건 환불·재발행 비용보다 **신뢰 비용**이 크다. 체험단 리뷰·후기로 유입을 만들기 시작한 단계에서 "돈 냈는데 안 온다"가 한 번씩 보이면, 그 뒤 모든 마케팅이 무효가 된다.

**이번 주 처리 (클로드)**
1. 실패 지점을 로그로 고정: 생성 실패·검사 실패·발송 실패를 구분해 남기고, 실패한 주문 식별자를 남긴다.
2. 검사에서 걸린 건이 **자동 재시도 1회 → 그래도 실패하면 사람에게 알림**으로 흐르게 한다. 조용히 멈추는 상태를 없앤다.
3. 동·호수 매칭: 신청 값(동/호수)과 조회 값(건축물대장·실거래)을 대조하는 검증 단계를 넣고, 불일치면 발행하지 않고 보류한다. **틀린 리포트를 보내느니 안 보내는 게 낫다.**
4. 발송 SLA를 지킬 수 있게 대기열 상태를 사용자에게 보여 준다(접수 → 생성 중 → 발송 완료).

**완료 판정**: ① 최근 실패 건 전부 재발행 완료 ② 새 주문 5건을 연속 자동 생성해 사람 손 없이 발송 ③ 동·호수 불일치 테스트 케이스에서 보류가 걸린다.

### 병목 B. 결정타가 없다 — "내가 상투 잡는 건가"에 답하지 못한다
지금 리포트는 **"이 자리가 어떤 자리인가"**에는 답하지만, 이사·매수자가 실제로 돈을 쓰는 이유인 **"이 값이면 사도 되는가"**에는 답하지 않는다. 무료 화면을 다 봐도 마지막 클릭을 만들 문장이 없다.

**설계안 — 적정 매수가 판정(신호등) 섹션**
종합 리포트(39,000원)와 비교 리포트(50,000원) 안에 한 블록으로 넣는다. 새 상품을 만들지 않는다.

- **입력**: 신청 주소 1곳(+ 비교 상품이면 2곳).
- **비교 기준**: ① 같은 동·같은 유형(아파트/연립/상가) ② 반경 1~2km 같은 유형 ③ 같은 구(시·군) 중위값. 기간은 최근 6~12개월 실거래로 통일하고 기준일을 반드시 적는다.
- **지표**: 평당가(또는 ㎡당가) 중위값, 거래 건수, 신축·구축 구분, 같은 단지 내 최근 거래 범위. **표본이 3건 미만이면 판정하지 않고 "자료 부족"으로 표시**한다.
- **판정**: 3단계 신호등 — 반경 중위값 대비 `-10% 초과 낮음 / ±10% 안쪽 / +10% 초과 높음`. 색과 함께 **왜 그렇게 나왔는지 한 줄**(예: "반경 1km 같은 유형 최근 6개월 12건 중위 1,850만 원/평, 이 단지는 2,030만 원/평").
- **문구 원칙**: "적정", "주의" 같은 판단 라벨은 쓰되 **"오른다/내린다/수익" 류의 단정은 쓰지 않는다.** "실거래 참고 지표이며 감정평가·투자 권유가 아니다. 계약 전 현장과 등기·건축물대장을 직접 확인하세요"를 같은 화면에 둔다.
- **명당 점수와 섞지 않는다**: 명당 점수는 지형 해석 점수다. 적정가 판정은 **별도 블록**으로 두고, 두 숫자를 하나의 "종합 판단"으로 합치지 않는다. 사이트가 이미 "집값·안전성 평가가 아니다"라고 밝히고 있으므로 이 선을 지켜야 기존 신뢰 자산이 유지된다.
- **무료 쪽에도 맛보기**: 무료 화면에 "반경 시세와 이 단지 시세의 차이"까지만 보여 주고, 해석·판정·체크리스트는 유료에 둔다.

**완료 판정**: 주소 3곳(수도권 아파트, 지방 아파트, 상가)에서 판정 블록이 실제 값으로 생성되고, 표본 부족 케이스에서 "자료 부족"이 뜬다.

### 병목 C. 유입 → 결제창이 끊긴다
**확인된 것 (2026-11-15 14:00 전후 라이브 확인)**
- 유료 상품 4종이 **같은 화면에 나란히** 놓여 있다(5,000 / 15,000 / 39,000 / 50,000). 첫 방문자에게는 "무엇을 골라야 하나"가 그 자체로 마찰이다.
- 「우리 집 한 장」(5,000원)과 「두 곳 비교 리포트」의 구매 버튼이 **비활성(disabled/aria-disabled=true)** 상태로 렌더링됐다. 같은 시점 「종합 리포트」(39,000원)·「자리 브리프」(15,000원) 버튼은 활성. **가장 싼 진입 상품이 잠겨 있으면 퍼널 3단계가 성립하지 않는다.** (선택 단계 진입 전 일시 상태일 가능성도 있어 원인 확인이 먼저다. 클로드 확인 항목.)
- 후기 영역이 `-`로 표시되고 후기 수·평균 별점이 채워지지 않은 상태로 보였다(로딩 시점 문제인지 데이터 없음인지 미확인). **사회적 증거가 화면에 안 보이면 5,000원도 39,000원도 결정이 어렵다.**
- 유입 채널(스레드·블로그·체험단)에서 온 사람이 **어느 상품으로 들어와야 하는지**가 정해져 있지 않다. 채널별 착지 상품·문구·UTM이 없다.

**이번 주 처리**
1. (클로드) 5,000원·비교 상품 버튼이 잠긴 조건을 확인하고, **정상 판매 상태면 열고, 의도적으로 닫은 것이면 화면에 이유를 적는다.**
2. (피클) 채널별 착지 설계: 스레드/클립 → 「우리 집 한 장」, 블로그 체험단 → 「종합 리포트」, 비교 검토자 → 「두 곳 비교」. 링크에는 UTM을 붙인다(규격은 퍼널 스킬 6장).
3. (피클) 후기 최소 3건을 실제 고객 동의 하에 확보해 화면에 노출. 후기에는 개인정보를 싣지 않는다(사이트 방침 그대로).
4. (피클) 결제 직전 이탈 지점 추적: PostHog 연동 후 `리포트 카드 클릭 → 폼 열림 → 주소 입력 → 결제창 호출 → 승인` 각 단계 이벤트를 심는다. 연동 전에는 서버 접수·승인 로그의 건수 차이로 대체한다.

**완료 판정**: 5,000원 결제가 실제로 완결되고, 채널별 착지 링크 4종이 UTM과 함께 동작하며, 단계별 이벤트가 쌓인다.
